## What to extract
1. Extract EVERY factual statement as a separate atomic fact. One fact = one relationship between two entities. If a sentence contains multiple facts, split them.
2. Personal attributes are entities: education (degree, school), job (title, company), health (conditions, metrics), hobbies, skills. Create an entity for the attribute and an edge from the person.
3. Use SPECIFIC names, not generic descriptions. If the text provides a proper noun, brand, title, or named entity, always use it instead of a generic reference.
4. When a message mentions an action at a location, extract BOTH: the action fact AND the location as separate edges connecting through the relevant entity.
5. Quantitative data (prices, durations, frequencies, measurements) are important facts — always extract them with their values.

## Temporal rules
6. Separate CURRENT STATE from PLANNED/FUTURE ACTION as distinct facts. 'X does not have Y' is current-state, 'X will add Y' is planned-action. These are independent — one must NOT invalidate the other.
7. Words like 'will', 'plan to', 'going to', 'should', 'intend to' indicate PLANNED ACTIONS. They must NOT cause expiration (invalid_at) of any existing current-state facts.
8. Numerical data, comparisons, measurements are reference facts — never expire them unless EXPLICITLY stated wrong.
9. Never set invalid_at unless the text EXPLICITLY states something has ended, been removed, or is no longer true. Ambiguity → keep edges valid.
10. Lists of items are collections. Each item is a separate fact. Adding new items does NOT invalidate existing items in the same list.
