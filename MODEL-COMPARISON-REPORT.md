## 2. Анализ качества извлечённых данных (Entities)

### 2.1 Сценарий 001: New Year Party

#### flash-lite (38 entities)
**Сильные стороны:**
- Хорошо извлекает персоны (Andrey, Boris, Vika, Galya) с детальными summary
- Корректно фиксирует цены и суммы в summary
- Создаёт отдельные entities для каждого продукта (champagne, vodka, wine, etc.)

**Слабые стороны:**
- Меньше контекстных entities (нет "partygoers", "shopping list", "decorations" как обобщений)
- Меньше связей между концепциями

**Пример entity (Boris):**
```
"Boris added vodka (2 bottles), red wine (3 bottles)... totaling 14000 rubles.
He marked his task as completed."
```

#### flash (49 entities)
**Сильные стороны:**
- Все преимущества flash-lite ПЛЮС:
- Создаёт обобщающие entities: "partygoers", "shopping list", "decorations", "desserts", "snacks"
- Лучше группирует связанные концепции
- Дополнительные entities: "alcohol", "board games", "vegetables", "bakery"

**Пример дополнительных entities:**
- `"partygoers"` - обобщение всех участников с полным списком покупок
- `"vegetables"` - группировка томатов, огурцов, картофеля
- `"decorations"` - группировка шаров, гирлянд, салфеток

**Вывод:** flash извлекает на 29% больше entities, создавая более богатый граф знаний с обобщениями и группировками.

### 2.2 Сценарий 002: Personal Budget

#### flash-lite (32 entities)
**Особенности:**
- Создаёт **5 дублирующихся entities для Marina** с разными состояниями бюджета
- Это показывает темпоральное отслеживание, но создаёт избыточность
- Хорошо извлекает категории бюджета и магазины

**Проблема дублирования Marina:**
```
"Marina", "Marina's December budget is 68000 rubles..."
"Marina", "Marina's December budget: Food & groceries: 25000..."
"Marina", "Marina set a December budget of 68,000 rubles..."
(и ещё 3 версии)
```

#### flash (36 entities)
**Особенности:**
- Также создаёт дублирующиеся entities для Marina, но меньше (3-4)
- Добавляет более специфичные entities: "cafe", "shopping", "groceries"
- Лучше структурирует отдельные транзакции

**Дополнительные entities:**
- `"cafe"` - отдельная entity для обеда
- `"shopping"` - обобщение всех покупок с историей изменений
- `"groceries"` - консолидация всех продуктовых покупок

**Вывод:** flash создаёт на 12.5% больше entities с лучшей структурой, хотя обе модели страдают от дублирования персоны.

## 5. Проблемы и рекомендации

### 5.1 Общие проблемы обеих моделей

1. **Дублирование персон**: Обе модели создают множественные entities для одного человека при обновлении состояния
   - flash-lite: до 6 дубликатов
   - flash: до 4 дубликатов
   - **Рекомендация**: Настроить Graphiti на merge entities с одинаковым именем

2. **Дублирование ингредиентов**: Некоторые ингредиенты (Salt, Butter) создаются как отдельные entities несколько раз

### 5.2 Преимущества flash

1. **Больше данных**: +14% entities, +17% edges
2. **Лучшая структура**: Обобщающие entities (categories, groups)
3. **Контекстные источники**: "butcher", "supermarket", "bakery"
4. **Лучшее форматирование ответов**: Подкатегории, эмодзи, фазы
5. **Быстрее**: На 3% быстрее в среднем (удивительно!)

### 5.3 Преимущества flash-lite

1. **Стоимость**: Дешевле (важно для production)
2. **Достаточная точность**: Все расчёты корректны
3. **Компактность**: Меньше избыточных entities

### Рекомендация

**Использовать gemini-2.5-flash для Graphiti** по следующим причинам:

1. Извлекает больше полезных данных (+14% entities, +17% edges)
2. Создаёт более структурированный граф знаний
3. Работает быстрее несмотря на более сложную обработку
4. Даёт более качественные ответы с лучшим форматированием

**Когда использовать flash-lite:**
- Для простых задач классификации (уже используется)
- При жёстких ограничениях бюджета
- Для прототипирования
